# 验证记录与边界

本文记录自动化检查环境、回归范围、当前结果和真实环境验收限制。所有检查均从仓库根目录执行。

## 本地自动化验证

开发环境为 Python 3.15.0、pytest 9.1.1、Ruff 0.17.0。运行环境的 `tzdata` 位于仓库 `.qa_deps`，pytest 临时目录也应放在该目录下；每次使用新的 basetemp 名称：

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) ".qa_deps")
$runId = "pytest-" + [guid]::NewGuid().ToString("N")
python -m pytest -q --basetemp (Join-Path ".qa_deps" $runId)
ruff check .
ruff format --check .
git diff --check
```

自动化回归覆盖 RSS/Atom/XML 解析、危险地址和重定向校验、抓取调度与共享源去重、订阅和投递状态持久化、失败恢复、管理 API，以及媒体与 AI 翻译渲染。翻译用例覆盖提供商未配置时不调用模型、提示词与 RSS 内容分离、目标语言跳过协议、混合语言段落处理、失败回退原文、提示词隔离缓存及源文章不被修改。媒体用例覆盖图文 RSS 中重复的 `View image` 链接和缩略图清理、纯视频路由，以及关闭媒体发送时保留链接并跳过插件下载。

按源翻译回归覆盖关闭开关时保留原文且不调用模型、共享列表中只翻译开启的源，以及翻译缓存复用；关闭源后即使已有缓存也仍返回原文。本地 UI harness 验证了开关默认关闭、开启并保存后列表显示开启、重新进入详情仍保持开启、关闭后状态恢复，以及新建源可开启翻译且成功后表单重置为关闭；这些交互使用内存假数据，不涉及真实平台。

本轮翻译诊断回归还覆盖长度受限的分段翻译、单段/单请求失败隔离、无效标记预算内二分、`SKIP` 与译文未变化的区分、失败结果不缓存、共享并发请求去重、一个等待者取消不影响共享任务、LRU 缓存淘汰以及运行时关闭时取消和清理翻译任务。测试记录的状态、原因和段数会在重启后保留；渲染失败不会丢失历史；旧 v3 备份可恢复，畸形诊断备份会被拒绝。

回归用例覆盖插件元数据中的 `telegram` 与 `lark` 平台声明，以及 Discourse/Linux.do RSS 自动生成标题锚点的清理；标题文字、普通 hash 链接和跨站同形链接会保留。

抓取间隔回归覆盖 `d`、`h`、`m`、`s` 换算、大小写与空白、无单位默认秒、旧整数配置及迁移优先级、源和列表的零值继承，以及非法输入拒绝。服务、管理 API 和 JSON 导入统一按秒存储，导入验证失败不会产生部分写入。WebUI 通过 Node VM 检查解析边界及源保存、列表创建和列表保存三个入口的提交与非法输入阻断。

1.1.1 补充宿主配置保存类型校验：旧整数转为数字字符串，`1h`、无单位数字与含空白的大小写单位输入在保存、重载后保持原文，迁移幂等；运行时才转换为秒。源和列表的 `poll_interval_input` 与秒值同事务保存，详情、目录、重启、JSON 导入导出及备份恢复保持原始填写值，错误或过期展示元数据不会覆盖调度秒值。

本轮本地 UI fake harness 还验证了消息列表/详情中的翻译诊断，以及从源详情进入测试记录后重新打开时 `partial`、超时和段数信息仍显示。界面核对使用假 provider 和内存数据，没有真实发送消息。

Feed HTML 用户样本在解析阶段转换成 Markdown，缓存与存储只保留一个 Markdown 内容块。Markdown token 回归检查标题、段落、嵌套强调、链接、表格降级、内联/代码块字面内容、媒体位置和旧块缓存兼容。Telegraph 回归检查只输出官方允许的节点和 `href`/`src` 属性、安全 HTTP(S) 地址、粗体后紧邻中文的排版、媒体顺序、64 KiB 截断仍保留有效节点及原文链接。AI 翻译通过 Markdown 标记保护、原文/译文段落配对、链接/媒体资源只出现一次、代码中的 `**` 字面内容、损坏标记回退和源文章不突变回归。

## 本地集成核对

本地集成测试使用 fake AI/provider 和文章数据，确认配置提示词作为模型系统提示，RSS 标题和正文作为独立用户输入；默认目标语言为 `[简体中文]`，替换为 `[英语]` 后目标随之改变。已是目标语言的标题或段落只保留一次；不同提示词使用独立缓存，相同提示词可复用缓存。测试未调用真实 AI 服务。

集成测试确认默认渠道与 Telegram 直接渲染 Markdown；Feishu 图文卡片复用 AstrBot 已配置的 Lark client，上传图片/视频并清理重复链接与关联缩略图。Feishu 纯视频走 AstrBot URL-based Video operation，由适配器下载发送；关闭 `media.send_as_media` 时使用源链接并跳过插件媒体下载。此处使用本地 fake/桩接口，没有发送真实平台消息。

Linux.do 的标题锚点经解析和旧缓存清理后，在默认渲染、飞书渲染和 Telegraph 节点中均不再输出锚点 URL 或 `¶`，标题文本及正常站内/跨站链接保留；缓存清理不修改原文章对象或其 hash。检查使用本地数据和桩接口。

2026-10-27，1.2.0 全量检查为 `450 passed, 9 warnings`（18.03 秒）。其中 6 条为 Windows curl selector 提示，3 条为 feedparser 弃用提示（`updated_parsed` 2 条、`updated` 1 条）。全仓 `ruff check`、`ruff format --check`（93 个文件）、`node --check views/rss/app.js` 和 `git diff --check` 均通过；diff 检查只有 CRLF 警告。

## 2026-10-31 本轮审查最终结果

全量 pytest 为 **494 passed, 6 warnings**（21.86 秒；Python 3.15.0、pytest 9.1.1）。6 条提示均来自 Windows 下 `curl_cffi` 使用 Proactor 兼容额外 selector 线程；本轮没有 feedparser 弃用警告。

全仓 `ruff check .` 通过；`ruff format --check .` 确认 97 个文件已格式化；`node --check views/rss/app.js` 和 `git diff --check` 通过。新增回归包括文章列表批量读取、多卡片失败恢复、完整维护清理、翻译诊断历史、并发缓存去重和运行时关闭清理。

本轮 UI 核对使用本地 fake harness，检查了消息/测试记录中的诊断状态展示。没有真实 AstrBot 宿主、AI provider 或平台凭据；未检查真实生产失败文章或日志，也没有向真实平台发送消息。因此回归结果验证了代码路径和诊断链路，不代表真实 provider 或平台端到端验收。
